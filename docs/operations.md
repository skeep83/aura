# Эксплуатация

## Админ-панель

**Aura Admin** — приложение `aura-admin` на TrueNAS: **http://192.168.4.166:30190** (только домашняя сеть, вход по паролю).
Обзор в реальном времени и графики за 14–90 дней (в том числе нити, приглашения, Duo, камера), пользователи (поиск, карточка с режимами, нитями и друзьями, бан/разбан, Premium, салюты, аура, отключить, написать через бота),
жалобы, платежи с возвратом Stars, модерация (включая скрытые ходы нитей), нити (список по статусу и типу, карточка с ходами, скрыть ход, в архив), комнаты, реклама, ИИ, Jev, система (эфиры, вдвоём, ссылки, все настройки).

- Панель ходит в продакшен по `https://aura-life.online/api/admin/*` с токеном `ADMIN_API_TOKEN` (в `.env` на VPS и в `admin.env` на TrueNAS).
  Браузер токен не видит. Без токена в `.env` админ-API выключен (404); 10 неверных попыток с одного IP — блок на 10 минут.
- Пароль: `ssh -t skeep@192.168.4.119 '~/.hermes/hermes-agent/venv/bin/python ~/aura-deploy/set_admin_password.py'` (хранится только scrypt-хэш).
- Обновить панель: `bash deploy/truenas/admin_update.sh`.

## ИИ

Провайдер подключается в админ-панели (раздел «ИИ»): OpenAI, Anthropic, OpenRouter, Gemini, Groq, DeepSeek или свой OpenAI-совместимый сервер (vLLM/Ollama).
Ключ хранится в таблице `settings` на VPS и в браузер не отдаётся (только последние 4 символа). Каждая функция включается отдельно, есть суточный лимит запросов.

| Функция | Где | Что делает |
|---|---|---|
| Модерация чата | Mini App | второй слой после правил: угрозы, сексуализация детей, вымогательство, мошенничество, ненависть → страйк (3 за сутки — бан на сутки). Проверяет уже доставленное сообщение |
| Темы для разговора | Mini App | «Тема» в играх: вопрос на языке пары с учётом стран; если ИИ молчит 6 с — тема из списка |
| Перевод | Mini App | нажатие на сообщение собеседника (🌐); до 40 переводов в час |
| Итоги недели | Mini App | личная фраза в Aura Wrapped |
| Нити | Mini App | перевод ходов нити на язык читателя одним запросом (кэш в базе навсегда) и заголовок истории в финале; без ИИ — оригинал с флагом и 🌐 |
| Аналитик и разбор | Админка | вопросы по метрикам за 30 дней; «ИИ-разбор» в карточке пользователя |

## Jev (TypeSafe AI)

Модель решений, а не чат: на вход — состояние, на выход — вероятности по типизированным вопросам (Noul — да/нет, Choice — выбор, Score — шкала).
Настраивается в админке, раздел «⚖️ Jev». Ключ — в таблице `settings`, в браузер не отдаётся.

| Функция | Что делает |
|---|---|
| Модерация чата | 5 вопросов «да/нет» по каждому сообщению (дети, угрозы, вымогательство, мошенничество, ненависть); выше порога (0.85) — страйк. Если Jev включён, он заменяет ИИ-модерацию |
| Разбор жалоб | после каждой жалобы — рекомендация «оставить / предупредить / бан 24 ч / бан 7 дн» с уверенностью (колонка в «Жалобах») |
| Автобан | только если включён: уверенность ≥ 90% и на человека уже ≥ 2 жалоб. Причина бана — `jev:<решение>` |
| Риск пользователя | кнопка «⚖️ Jev: риск» в карточке: шкала 0–4 и вероятность «бот/спамер» |

## Модерация чата

Правила (`src/chatfilter.js`) работают мгновенно: ссылки, @юзернеймы, телефоны и мессенджеры скрываются (контактами обмениваются через «Вайб»), мат маскируется,
тяжёлое (сексуализация детей, угрозы, «скинь нюдсы», шантаж) не доставляется и даёт страйк; одно и то же сообщение со ссылкой трём людям за 10 минут — рассылка.

## Кадры на модерацию обязательны

Через 25 с после начала разговора каждый участник должен присылать кадр хотя бы раз в 20 с (`FRAME_GRACE_MS`, `FRAME_MAX_GAP_MS`),
иначе разговор прерывается (`no_frames` в событиях). Если сервис модерации недоступен, проверка не применяется.

## Метрики

| Поле | Смысл |
|---|---|
| `online`, `waiting`, `talking` | сейчас в приложении / в очереди / в разговоре |
| `dau`, `newUsers` | уникальные за сутки / новые |
| `matches`, `ttmMedianSec` | разговоров и медианное время до собеседника (цель < 15 с) |
| `callMedianSec`, `quickSkipPct` | медианная длительность и доля «Далее» в первые 5 с |
| `connFailPct` | доля несоединившихся WebRTC (растёт без TURN) |
| `vibes`, `vibeMatches` | вайбы и взаимные вайбы |
| `reports`, `ageBlocks`, `nsfwStrikes` | безопасность |
| `premiumBuys`, `stars` | деньги |
| `d1` | удержание: из пришедших позавчера — вернулись за сутки |
| `sources` | откуда пришли: `room:<slug>`, `ref`, `invite`, `thread`, `direct` |
| `duos`, `duoQueue`, `duoInCall` | Duo сейчас: всего / в поиске / в звонке |
| `threadsLive`, `threadsPool`, `threadsDone` | нити: в карманах / в пуле (застрявшие) / завершённые |

Вирусные фичи пишут свои события (`guess_ok`, `compliment`, `salute`, `salute_buy`, `duo_create`, `duo_join`, `duo_call`, `thread_start`, `thread_show`, `thread_move`, `thread_done`, `thread_accept`, `thread_drop`, `thread_hide`, `pair_on`/`pair_off`, `duo_conn_ok`/`duo_conn_fail`, `invite_open`/`invite_join`/`invite_miss`) — по ним видно, что «залетает». Недельные итоги уходят в воскресенье в 19:00; отметка последней рассылки — `data/wrapped.week`.

События пишутся в таблицу `events` — можно строить любые срезы SQL-запросами.

## Диагностика соединений

Клиент сообщает итог WebRTC без IP-адресов; в логах api:

```
conn ok srflx>srflx turn=false
conn FAIL timeout local=host,srflx remote=srflx turn=false
```

Нет `relay` у несоединившихся → нужен TURN.

## Мониторинг

Сторож (`deploy/truenas/aura_watchdog.py`, systemd user timer раз в минуту) проверяет `https://<домен>/healthz` и `/healthz` модерации. Алерт в Telegram — после 3 провалов подряд и при восстановлении (без спама). Cloudflare отвечает 403 на User-Agent `Python-urllib` — в проверках задаётся свой.

## Бэкапы

- TrueNAS: периодический снапшот датасета приложения каждый час, хранение 2 суток (SQLite в WAL корректно восстанавливается из атомарного снапшота ZFS).
- Перед рискованными изменениями — ручной снапшот.
- VPS: ежедневный бэкап провайдера + `docker compose exec api sqlite3`/копия `/data` по расписанию.
- **Перед деплоем с миграцией схемы — ручная копия базы.** Миграции только добавляющие
  (`CREATE TABLE IF NOT EXISTS`, `ALTER TABLE ADD COLUMN`), но откат кода на предыдущую версию
  спокойнее делать, когда база заведомо цела:

  ```bash
  docker compose exec api sh -c 'cp /data/roulette.db /data/roulette.db.$(date +%F-%H%M).bak'
  ```

## Включение входа на сайте (AUTH_PROVIDERS)

Порядок раскатки такой, чтобы в любой момент можно было вернуться к прежнему поведению:

1. Деплой кода с **пустым** `AUTH_PROVIDERS`: `/auth/*` отдаёт 404, cookie не выдаются, кнопок входа в интерфейсе нет. Проверить `/healthz`, вход в Mini App и анонимный вход в браузере.
2. Копия базы по шагу выше: новая таблица `identities` и колонки `users` создаются при старте api.
3. Cloudflare: cache rule **bypass** для `/auth/*` — иначе `Set-Cookie` и редиректы могут закэшироваться.
4. Для Telegram Login — `/setdomain` у @BotFather на домен сайта и заполненный `BOT_USERNAME`.
5. Включать провайдеров по одному: `AUTH_PROVIDERS=telegram`, перезапуск api, живая проверка входа, затем следующий.
6. Откат — вернуть `AUTH_PROVIDERS=` и перезапустить api: новые cookie перестают выдаваться, профили и привязки остаются в базе.

## Модерация: разбор инцидентов

- Логи api: `nsfw <id> score=… strikes=…`, `age block <id> minor=…`, `report <a> -> <b> (reason)`.
- Разбан: `/unban <telegram_id>`; бан навсегда: `/ban <telegram_id>`; возврат Stars: `/refund <charge_id>`.
- Порог возраста консервативный (класс «10–19» включает 18–19 лет); при жалобах на ложные блоки — поднять `MINOR_THRESHOLD`.

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| «2 онлайн и не матчит» | Нет общего языка, фильтр пола, разные комнаты — либо пара сводится, но WebRTC не соединяется (смотреть `conn FAIL`) → TURN |
| Mini App не открывается | `/healthz`, логи `tunnel`/`web`; адрес в @BotFather должен совпадать с доменом |
| «Откройте через Telegram-бота» | `initData` не прошёл проверку: неверный `BOT_TOKEN` или открыто вне Telegram |
| Бот молчит | `BOT_TOKEN`, логи `getUpdates`; только один процесс может делать long polling |
| Профиль бота не обновился | меняется только при изменении текстов (хэш в `data/bot-profile.hash`); удалить файл → переотправка |
