# Эксплуатация

## Админ-панель

**Aura Admin** — приложение `aura-admin` на TrueNAS: **http://192.168.4.166:30190** (только домашняя сеть, вход по паролю).
Обзор в реальном времени и графики за 14–90 дней, пользователи (поиск, карточка, бан/разбан, Premium, салюты, аура, отключить, написать через бота),
жалобы, платежи с возвратом Stars, модерация, комнаты, настройки.

- Панель ходит в продакшен по `https://aura-life.online/api/admin/*` с токеном `ADMIN_API_TOKEN` (в `.env` на VPS и в `admin.env` на TrueNAS).
  Браузер токен не видит. Без токена в `.env` админ-API выключен (404); 10 неверных попыток с одного IP — блок на 10 минут.
- Пароль: `ssh -t skeep@192.168.4.119 '~/.hermes/hermes-agent/venv/bin/python ~/aura-deploy/set_admin_password.py'` (хранится только scrypt-хэш).
- Обновить панель: `bash deploy/truenas/admin_update.sh`.

## Метрики

`/stats` в боте (для `ADMIN_IDS`) — состояние и воронка за последние сутки:

| Поле | Смысл |
|---|---|
| `online`, `waiting`, `talking` | сейчас в приложении / в очереди / в разговоре |
| `dau`, `newUsers` | уникальные за сутки / новые |
| `matches`, `ttmMedianSec` | разговоров и медианное время до собеседника (цель < 15 с) |
| `callMedianSec`, `quickSkipPct` | медианная длительность и доля «Далее» в первые 5 с |
| `connFailPct` | доля несоединившихся WebRTC (растёт без TURN) |
| `vibes`, `vibeMatches` | вайбы и взаимные вайбы |
| `reports`, `ageBlocks`, `nsfwStrikes` | безопасность |
| `premiumBuys`, `stars` | деньги |
| `d1` | удержание: из пришедших позавчера — вернулись за сутки |
| `sources` | откуда пришли: `room:<slug>`, `ref`, `direct` |
| `duos`, `duoQueue`, `duoInCall` | Duo сейчас: всего / в поиске / в звонке |

Вирусные фичи пишут свои события (`guess_ok`, `compliment`, `salute`, `salute_buy`, `duo_create`, `duo_join`, `duo_call`) — по ним видно, что «залетает». Недельные итоги уходят в воскресенье в 19:00; отметка последней рассылки — `data/wrapped.week`.

События пишутся в таблицу `events` — можно строить любые срезы SQL-запросами.

## Диагностика соединений

Клиент сообщает итог WebRTC без IP-адресов; в логах api:

```
conn ok srflx>srflx turn=false
conn FAIL timeout local=host,srflx remote=srflx turn=false
```

Нет `relay` у несоединившихся → нужен TURN.

## Мониторинг

Сторож (`deploy/truenas/aura_watchdog.py`, systemd user timer раз в минуту) проверяет `https://<домен>/healthz` и `/healthz` модерации. Алерт в Telegram — после 3 провалов подряд и при восстановлении (без спама). Cloudflare отвечает 403 на User-Agent `Python-urllib` — в проверках задаётся свой.

## Бэкапы

- TrueNAS: периодический снапшот датасета приложения каждый час, хранение 2 суток (SQLite в WAL корректно восстанавливается из атомарного снапшота ZFS).
- Перед рискованными изменениями — ручной снапшот.
- VPS: ежедневный бэкап провайдера + `docker compose exec api sqlite3`/копия `/data` по расписанию.

## Модерация: разбор инцидентов

- Логи api: `nsfw <id> score=… strikes=…`, `age block <id> minor=…`, `report <a> -> <b> (reason)`.
- Разбан: `/unban <telegram_id>`; бан навсегда: `/ban <telegram_id>`; возврат Stars: `/refund <charge_id>`.
- Порог возраста консервативный (класс «10–19» включает 18–19 лет); при жалобах на ложные блоки — поднять `MINOR_THRESHOLD`.

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| «2 онлайн и не матчит» | Нет общего языка, фильтр пола, разные комнаты — либо пара сводится, но WebRTC не соединяется (смотреть `conn FAIL`) → TURN |
| Mini App не открывается | `/healthz`, логи `tunnel`/`web`; адрес в @BotFather должен совпадать с доменом |
| «Откройте через Telegram-бота» | `initData` не прошёл проверку: неверный `BOT_TOKEN` или открыто вне Telegram |
| Бот молчит | `BOT_TOKEN`, логи `getUpdates`; только один процесс может делать long polling |
| Профиль бота не обновился | меняется только при изменении текстов (хэш в `data/bot-profile.hash`); удалить файл → переотправка |
